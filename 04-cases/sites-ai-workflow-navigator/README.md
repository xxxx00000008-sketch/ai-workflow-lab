# 真实案例：AI 工作流导航站

> 日期：2026-09-19
>
> 状态：本地可运行，未部署
>
> 用户：第一次接触 ChatGPT Work、Codex 和 Sites 的中文用户

## 真实问题

现有知识库虽然解释了功能，但新用户仍不知道面对一个任务时应从哪里开始。这个案例把抽象说明变成一个可操作页面：用户选择目标和经验，立即获得匹配的工作流、步骤和第一条可复制提示。

## 可直接查看的产物

打开 [`site/dist/index.html`](site/dist/index.html) 即可使用。页面不需要安装依赖、不请求网络、不收集数据。

实际功能包括：

- 按学习、交付、开发和自动化筛选。
- 按第一次使用或已有实践筛选。
- 显示空状态和结果数量。
- 展开可直接使用的第一条提示。
- 支持键盘焦点、减少动效设置和移动端布局。

## 从需求到实现

### 输入

```text
为第一次接触 AI 工作流的人创建导航站。
用户选择目标和经验后，应知道选择 Chat、Work、Codex 还是自动化，并获得第一条可执行提示。
先完成本地版本，不部署，不收集用户数据。
```

### 关键决策

- 这是决策工具，不是营销页，因此第一屏直接展示筛选器和结果。
- 使用单文件静态站点，降低第一次运行门槛。
- 不加入登录、数据库、上传和外部连接，避免超出需求。
- 使用真实的工作流内容，不用占位卡片。
- 部署前必须先由用户审查；Sites 的部署 URL 属于生产部署。

### 目录

```text
sites-ai-workflow-navigator/
├── README.md
└── site/
    ├── .openai/
    │   └── hosting.json
    └── dist/
        └── index.html
```

## 手工验收

1. 双击打开 `site/dist/index.html`。
2. 选择“开发和发布”，确认只显示 Codex 路线。
3. 选择“第一次使用”，确认出现空状态。
4. 点击“重置筛选”，确认恢复四条路线。
5. 点击任一卡片的“查看第一条提示”，确认提示展开且按钮文案变化。
6. 缩窄浏览器窗口，确认卡片变为单列且没有横向滚动。
7. 仅使用键盘 Tab、Enter 和方向键完成筛选与展开。

## Sites 发布流程

当前案例刻意停在“本地可运行、未部署”状态。用户审查通过后，发布流程应是：

1. 在 ChatGPT Work 中调用 `@Sites`，选择当前兼容项目。
2. 要求检查项目兼容性并先保存，不要部署。
3. 审查页面、源码变化和任何托管配置变化。
4. 明确确认访问范围。
5. 用户明确批准后再部署并获取 URL。

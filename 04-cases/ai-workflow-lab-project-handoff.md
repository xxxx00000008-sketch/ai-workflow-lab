# 案例：用 ChatGPT Project 与 Codex 建立 AI Workflow Lab

## 背景

用户希望长期研究 ChatGPT、Codex、Claude Code 和其他 AI 工具，并把知识库按开源项目方式运营。早期讨论已经形成项目定位和目录构想，但 GitHub 仓库只有一个简短 README。

## 目标

把一次对话中的规划转化为可以持续维护、接受贡献和积累证据的公开仓库，并以 ChatGPT Projects 作为第一个研究闭环。

## 约束

- 不把规划中的目录误认为已经实现。
- 不伪造未执行的产品实验。
- 结论优先依据官方资料和真实操作记录。
- 变更需要进入独立分支并保留 Git 历史。

## 实施

1. 从用户引用的前序对话恢复项目定位、四层知识体系和 V0.1 顺序。
2. 读取本地仓库确认真实起点。
3. 建立八类内容目录、路线图、贡献规则、Issue/PR 模板和研究模板。
4. 创建 `codex/v0.1-initialization` 分支，验证并提交 29 个文件，推送至 GitHub。
5. 查阅 OpenAI Academy 的 Projects 官方资料。
6. 将官方事实、真实交接实验、可复用生命周期工作流和本案例互相链接。

## 工具分工

| 工具 | 在案例中的职责 |
| --- | --- |
| ChatGPT Project | 保存长期目标、对话背景和阶段连续性 |
| Codex 桌面端 | 检查仓库、编辑文件、验证与执行 Git 流程 |
| Git/GitHub | 保存权威状态、差异、分支和审查入口 |

## 结果

- 项目从单一 README 变为可扩展的开源知识库骨架。
- V0.1 路线和每个主题的完成标准变得可检查。
- Projects 主题形成知识卡、实验记录、工作流和案例四类互相引用的产物。
- 对话中的项目意图被转化为可版本化资产，后续任务无需从零解释整体结构。

## 复盘

真正提供可靠连续性的不是“把所有内容都放进上下文”，而是明确分工：Project 保存目标和协作背景，仓库保存权威事实，单次任务负责读取现状、完成小范围交付并把结果写回仓库。

最容易被忽略的风险是把对话里的计划当成当前状态。任何后续任务都应先检查仓库，再决定要做什么。

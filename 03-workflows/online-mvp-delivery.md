# 线上 MVP 项目交付工作流

> 状态：A3 工作流方案；尚未作为独立案例完成验证
>
> 证据等级：E0；目标自动化成熟度：M2
>
> 适用场景：客户已明确一个可在一至两周内交付的线上 MVP，团队使用企业微信、ChatGPT Project、代码仓库与实际发布环境协作。

## 目标

让新成员在不依赖口头传承的情况下，完成一个小型线上项目的需求确认、实现、验收和仓库交付。目标是客户确认的可用结果，不是“完成若干页面”或“代码已合并”。

## 最小协作面

| 系统 | 唯一用途 | 规则 |
| --- | --- | --- |
| 企业微信 | 对客户沟通、确认与日常进度 | 需求变更、验收和上线必须留下可检索文字确认 |
| ChatGPT Project | 研究、需求分析、方案草稿和决策上下文 | 不保存密码、密钥、未脱敏个人资料或最终唯一事实 |
| Git 仓库 | 已批准的需求、代码、测试、部署说明和变更历史 | 只有仓库中的批准交付契约可作为工程执行依据 |
| 预览/生产环境 | 演示、验收、发布和回滚 | 客户不直接在生产环境验收未测试的改动 |

## 标准目录（只列结构）

以下是实际项目仓库的建议目录；按真实技术栈调整，不因本工作流而创建空文件。

```text
project/
├── AGENTS.md
├── README.md
├── docs/
│   ├── delivery-contracts/
│   ├── decisions/
│   ├── data/

├── tests/

│   ├── integration/
```

`ai-workflow-lab` 只沉淀这类目录、流程和脱敏模板；客户访谈原文、账号信息、真实密钥、内部报价、源码和验收记录均留在客户授权系统，不进入知识库。

## 执行步骤

### 1. 启动与授权

输入：客户目标、上线期限、仓库访问权限、预览或发布权限。

操作：在企业微信确认唯一验收人、沟通节奏、发布权限边界和紧急联系机制；建立 ChatGPT Project 与 Git Issue/任务编号。

输出：项目摘要、联系人角色表、风险清单、单一任务看板。

门禁：没有验收人、仓库权限或可验证的交付路径时，不承诺上线日期。

### 2. 冻结交付契约

为每个交付项建立 `DELIVERY-项目-编号`，至少写明：用户问题、范围、不做事项、界面或 API 行为、数据来源、验收示例、测试、发布与回滚条件。

客户在企业微信确认后，将批准版本提交到仓库。聊天中的讨论稿不能覆盖该版本。

### 3. 建立可验证的垂直切片

先实现一条真实用户路径，从输入、数据、业务规则、页面到错误提示全部贯通。不要先铺满页面或接入所有数据，再等待核心路径可用。

每次改动应关联交付编号，使用独立分支或 worktree；Codex 先审查现状与测试方式，再实施受限范围内的变更。

### 4. 每日线上节奏

每天固定四件事：

1. 在企业微信发送“昨天结果、今天可验收产物、阻塞项”。
2. 将客户新要求分类为澄清、缺陷或范围变更；范围变更必须更新交付契约与排期。
3. 在预览环境演示当天的可用垂直切片，而不是只发送截图。
4. 在仓库中保留代码、测试、变更说明和运行方式；ChatGPT Project 只保存研究和决策摘要。

### 5. 质量门禁

发布前至少确认：关键路径可运行、测试通过、主要错误状态可理解、移动端基础可用、来源/文案/链接已复核、无密钥或个人数据进入仓库、有回滚方案。

涉及价格、医疗、金融、法律、账户或支付等高风险信息时，必须增加人工事实核验；AI 产出不能作为唯一证据。

### 6. 客户验收与交付

用交付契约中的验收示例带客户走一遍真实路径。验收不通过时记录复现条件和严重程度；通过时在企业微信获得明确文字确认。

仓库交付至少包含：运行说明、环境变量清单（只写名称，不写值）、部署说明、回滚步骤、已知限制和下一步建议。若客户授权正式发布，则补充发布编号和冒烟测试结果。

### 7. 复盘与知识库沉淀

只把可公开、可脱敏、可复用的内容沉淀到 `ai-workflow-lab`：流程调整、目录变化、模板字段、质量门禁和通用经验。不得提交客户原始资料或完整交付记录。

## 一周计划

| 天数 | 目标 | 最小可验收结果 |
| --- | --- | --- |
| 1 | 启动与范围冻结 | 批准的交付契约 |
| 2 | 数据/规则/原型确认 | 可追溯数据样本与原型 |
| 3–4 | 实现核心垂直切片 | 预览环境可操作主路径 |
| 5 | 完成功能、测试与异常处理 | 发布候选版本 |
| 6 | 客户验收和修复 | 通过的验收清单 |
| 7 | 发布或仓库交付 | 可运行仓库与交付说明 |

## 失败处理

- 客户新增超出范围的功能：建立下一交付项，不以压缩测试换取“本周完成”。
- 数据或第三方接口不可用：展示明确状态，降级为人工可维护的数据集，不伪造实时数据。
- 发布权限缺失：交付可部署仓库和部署说明，标记为“待客户发布”，不声称已经上线。
- 验收标准冲突：停止实施争议功能，要求验收人更新交付契约。

## 完成定义

客户能够按验收示例完成核心任务；代码仓库可由授权方运行或部署；已知限制透明；客户通过可检索渠道确认验收；方法库只保留脱敏、可复用的流程改进。

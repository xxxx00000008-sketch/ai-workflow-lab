## 要回答的问题

1. Project 与普通对话的边界是什么？
2. 项目指令、上传资料、对话历史和 Memory 分别如何影响回答？
3. 一个长期项目应如何组织上下文，避免信息过期或相互污染？
4. 哪些内容适合长期保存，哪些应留在一次性对话中？
5. Projects 如何与 Git 仓库、Codex 任务和外部知识库配合？

## 初始假设

- Projects 更适合持续目标和共享上下文，而不是单次问答。
- 稳定规则应写入项目说明或仓库规范；快速变化的信息应保留来源与日期。
- 上下文越多不一定越好，需要按任务维护和清理。

以上均为待验证假设，不作为产品事实。

## 实验计划

- 使用同一问题对比普通对话与 Project 对话。
- 分别改变项目指令、项目文件和对话上下文，观察其影响。
- 测试新对话能否正确继承项目上下文，以及继承的边界。
- 引入一条过期信息，测试发现、纠正和维护成本。
- 记录隐私、权限、文件限制和协作场景中的异常。

实验结果写入 [`07-experiments/chatgpt/projects/`](../../07-experiments/chatgpt/projects/)。完成实验前，不在此页写确定性结论。

# AI-native 项目启动工具包

> 用法：新项目按顺序复制相应模板，填写后放入客户授权的系统或实际项目仓库。不要把客户原始内容提交到 `ai-workflow-lab`。

## 1. 项目启动摘要

```text
项目名称：
客户目标：
目标用户：
用户必须完成的一个核心任务：
一周/本期交付物：
明确不做：
唯一验收人：
需求联系人：
仓库负责人：
发布负责人：
截止时间：
现有 Demo / 仓库 / 环境：
缺失权限与阻塞：
```

AI 的作用：把客户材料整理为草稿、发现矛盾和缺失项。人工控制点：客户目标、范围、联系人和权限必须由客户确认。

## 2. 工具与信息归属表

```text
企业微信：客户确认、进度、演示、验收
ChatGPT Project / Work：研究、分析、方案和决策摘要
Git 仓库：批准的交付契约、代码、测试、部署说明
Codex：读取仓库、实现、测试、Diff 审查
预览环境：每日演示和客户验收
生产环境：经批准的正式发布
```

为每项补充实际链接、负责人和权限。密钥只进入批准的密钥管理系统，不进入本表。

## 3. 交付契约

```text
交付编号：
版本与批准日期：
客户验收人：

用户问题：
核心用户路径：
本次范围：
明确不做：

功能行为：
数据来源与更新要求：
空状态、错误状态和权限状态：

验收示例 1：
验收示例 2：
验收示例 3：

必须通过的测试：
发布方式：
回滚条件：
已知限制：
待确认项：
客户批准记录：
```

AI 的作用：把已确认信息转换为可测试行为，指出不可验收的表述。人工控制点：范围、事实来源、风险、发布和批准。

## 4. 每日线上更新

```text
日期：
今天完成并可演示的结果：
预览地址或提交：
对应的验收示例：
测试结果：
发现的风险或阻塞：
需要客户确认的问题：
明天计划：
范围是否变化：否 / 是（若是，返回更新交付契约）
```

## 5. 客户验收清单

```text
版本或提交：
预览/生产地址：
验收人：
验收时间：

[ ] 核心用户路径可完成
[ ] 三个验收示例符合交付契约
[ ] 主要错误和空状态可理解
[ ] 数据、来源和关键文案已核对
[ ] 移动端或约定设备可用
[ ] 已知限制已经说明
[ ] 启动、部署与回滚说明可用

阻断问题：
非阻断问题：
验收结论：通过 / 有条件通过 / 不通过
客户确认记录：
```

## 6. AI-native 复盘

```text
哪一步最耗时，为什么：
哪一次 AI 输出造成返工，为什么：
哪一项人工确认避免了风险：
哪些上下文未能正确交接：
哪些检查可以模板化或自动化：
新人最容易卡在哪里：
本次应修改的 ai-workflow-lab 文件：
可升级为模板 / Skill / Automation 的内容：
不得沉淀的客户敏感内容：
```

复盘完成的标志不是写完总结，而是至少更新一条可复用规则、模板或失败处理；如果本次没有可靠证据，则只记录“待验证”，不包装成最佳实践。

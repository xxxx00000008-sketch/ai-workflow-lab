# 实验：用 Codex 桌面端补齐 ChatGPT 与 Codex 知识库

> 日期：2026-09-19
>
> 环境：Windows ChatGPT 桌面应用、Codex、本地 Git 仓库、官方 OpenAI Docs
>
> 结果：通过（限定于文档型本地交付）

## 问题

Codex 是否能在一个已有仓库中完成“研究当前官方资料、读取项目规范、批量编辑文档、校验链接、维护路线图、提交并推送”的端到端任务？

## 步骤

1. 读取仓库 `AGENTS.md`、路线图和现有主题。
2. 搜索并打开 ChatGPT Work、Codex 桌面端、AGENTS.md、Plugins、Scheduled 与权限的官方页面。
3. 尝试获取官方 Codex 手册；首次因网络限制失败，授权联网后返回 HTTP 403，记录限制并改用已打开页面。
4. 创建 ChatGPT 剩余主题、Codex 功能地图、选择指南和桌面交付工作流。
5. 区分官方说明、当前环境观察和必须在特定账号中继续验证的功能。
6. 运行 Markdown 相对链接、格式和 Git 差异检查。

## 观察

- Codex 能把网页研究与本地仓库编辑连接成同一任务。
- 仓库规范和现有文件提供了比对话记忆更可靠的当前状态。
- 权限审批允许对受限网络和 Git 元数据写入进行显式控制。
- 外部手册接口不可用时，需要保留失败证据并降低结论范围。
- 批量文档修改仍必须通过链接检查和 Diff 审查发现机械错误。

## 结论

在文档型项目中，Codex 桌面端可以完成从研究到版本化交付的闭环。可靠性来自工具反馈、仓库状态和人工审查，而不是一次提示本身。

本实验没有验证云端执行、多个 Agent 同时写入、共享插件权限或无人值守 Automation。
